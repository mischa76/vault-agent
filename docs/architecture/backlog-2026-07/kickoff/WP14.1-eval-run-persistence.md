# Kick-off WP14.1 — Crash-safe eval-run persistence (eval-only, one commit)

You are a senior Python engineer working on **vault-agent** (this repository). Your task
is one small operational fix from the live scale protocol: a mid-batch failure must
never lose completed, paid-for repeats again. The findings entry is the spec:
`docs/architecture/scale-test-findings.md` → **Candidate #3** (a real run 1/3 was lost
when the API credit balance ran out during run 2/3 — `_write_results` only runs after
the whole batch). **No file under `src/vault_agent/` may change.**

## Read first, in this order
1. `docs/architecture/scale-test-findings.md` — Candidate #3 (symptom, cost, proposal).
2. `eval/run.py` — `_run_and_score`, `_write_results`, `main` (the batch loop you
   restructure); note the result-filename scheme is already one timestamped JSON per
   repeat — you are changing *when* files are written, not *what*.
3. The existing runner tests (payload-shape and no-key tests) — your regression
   baseline; the JSON content for a fully successful batch must stay identical.

## Task
- Write each repeat's result JSON (scores + `metrics` + `mappings` dump) **immediately
  after that repeat is scored**, inside the loop — not after the batch.
- On an exception during repeat *k*: everything up to *k−1* is already on disk; print
  which repeat failed and why, and exit non-zero. Do not retry (the ForcedToolCaller
  already handles retryable errors; a 4xx like an empty credit balance must stay fatal).
- Console summary (aggregate table, metrics, gate verdicts) keeps rendering after the
  batch as today — from the in-memory results of the completed repeats when the batch
  was cut short, clearly marked as partial (`n/m runs completed`).
- LangSmith upload (if configured) uploads only completed repeats — unchanged behaviour
  otherwise.

## Constraints
- eval-only; identical JSON shape and identical console output for a fully green batch
  (regression-pin the success path).
- Keyless tests via the existing stub-graph path: (a) an injected failure on repeat 2 of
  3 leaves repeat 1's JSON on disk, prints the partial summary, exits non-zero;
  (b) success path byte-equivalent to today.
