# Work-package specs (`backlog-2026-07/`)

Every work package of vault-agent has its spec here, one file each: `wp<N>-<topic>-spec.md`, from WP1
(July 2026) to the latest. The folder kept the name of the backlog it started with; it was never closed.

**Where to start:** the [work-package table in the documentation index](../../index.md#work-package-specs)
— one row per WP with a one-line summary and its state (specced, built, measured, with dates). That
table is maintained; the specs themselves are append-only records (a later finding is a new entry in
[`docs/log.md`](../../log.md), never an edit here).

Also in this folder:

- [`00-overview.md`](00-overview.md) — the original July 2026 plan for WP1–WP10 and its execution
  waves; historical, not updated since.
- `kickoff/` — the self-contained kick-off prompts of the early work packages.
- Charters and results of the design spikes: [mapping](spike-mapping-charter.md) →
  [results](spike-mapping-results.md), [entity resolution](spike-entity-resolution-charter.md) →
  [results](spike-entity-resolution-results.md), and the
  [incremental-extension charter](incremental-extension-charter.md) behind brownfield mode.

Backlog candidates that are not yet work packages live one level up:
[`backlog-2026-10-candidates.md`](../backlog-2026-10-candidates.md) and
[`backlog-2026-10-candidates-2.md`](../backlog-2026-10-candidates-2.md).
